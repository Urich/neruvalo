# Neruvalo: реализовано и остаётся сделать

Проверка исходников ветки `prototype/desktop-core`, версия 0.4.0, 30.10.2026. Это статус реализации, а не изменение требований. Исторические разделы руководства/спецификации могут описывать более ранние сборки.

## В этой итерации

- Общие копии по логину между аккаунтами одного сервера: отдельные зашифрованные контейнеры и sealed box ключа для каждого получателя, подпись контекста и контейнера владельцем.
- Атомарное обновление всех действующих копий вместе с новой версией оригинала. Изменение состава получателей конфликтует со старым сохранением.
- Отзыв владельцем, отказ получателя, прекращение доступов при архивировании оригинала/поддерева. Восстановление не возвращает прежние доступы. Повторная выдача создаёт новые ID.
- Получателю доступно только текущее содержимое, без API редактирования и истории чужого оригинала. Копия не содержит групп, тегов и служебных полей владельца.
- «Поделиться» в карточке/меню, проверка логина и ключей, подтверждение передачи, список получателей и отзыв. «Полученные», «Убрать у меня», индикатор и фильтр «С общим доступом».
- Базовое уведомление в приложении при обнаружении новых входящих копий во время загрузки/синхронизации. После нового входа уведомление может появиться повторно; это не полноценный центр непрочитанных уведомлений.
- Офлайн-чтение последней проверенной входящей копии; после успешного полного снимка прекращённые копии убираются из рабочего кеша и открытой карточки. Локальные служебные метки сохраняют максимальную ревизию, отпечаток текущего контейнера и факт прекращения доступа: повтор старого ID после подтверждённого удаления, снижение ревизии и иной контейнер с той же ревизией отклоняются. При полной потере кеша эти локальные знания теряются.
- Протокол 2, новая схема сервера/кеша 2, явный отказ базе 1 без автоматического удаления. Текущая версия содержимого обычных записей остаётся 1, групп — 2, общих контейнеров — 2.

Синхронизация пока полным снимком; действующие копии хранятся отдельно от истории оригиналов. Служебные строки прекращённых доступов остаются на сервере, их текущие контейнеры очищаются. В SQLite/PostgreSQL для согласованности снимков, доступа и записи используется единый транзакционный guard в metadata. Он намеренно сериализует записи всех аккаунтов прототипа; масштабирование и более узкие блокировки — отдельная работа.

## Требования документации, которые ещё не выполнены

|---|---|---|
| Общие копии: QR | Ввод/сканирование и отображение QR идентичности. Сейчас получатель выбирается по логину; отображаются ключи и отпечаток | `ShareDialog.tsx`, `client-core/src/sharing.rs` |
| Ключи общих копий | При смене закреплённого ключа операция блокируется. Пользовательская процедура подтверждённой замены/ротации ещё не реализована | `client-core/src/sharing.rs` |
| Уведомления | Долговечный центр уведомлений/непрочитанных, выбор каналов, системные и мобильные push, серверный журнал событий | `App.tsx`, `server/src/sharing.rs` |
| Синхронизация | Delta с курсорами, WebSocket/push-сигналы, журнал изменений с восстановлением по курсору; ограничения и пагинация больших хранилищ | `Client::sync`, `server::snapshot` |
| Регистрация в интернете | Реальный SMTP, CAPTCHA, производственная настройка лимитов и защита публичного сервиса. Email-коды пока в dev-outbox; сервер разрешён только на loopback | `server/src/main.rs`, `server/src/lib.rs` |
| Управление аккаунтом | Обычная смена пароля, подтверждённая смена email, явное необратимое удаление аккаунта с историей и общими доступами | Доступные маршруты сервера и команды клиента |
| Сертификат восстановления | Замена и отключение после регистрации. Создание при регистрации и восстановление секретным файлом уже есть | `client-core/src/lib.rs`, команды Tauri |
| Устройства и сессии | Список устройств, отдельные имена/идентичности устройств, отзыв выбранной сессии/устройства, интерфейс управления ими | Схема `sessions`, маршруты сервера |
| Windows Hello / TPM | Привязка ключей к TPM/Hello и системная разблокировка. Обработчики блокировки Windows/сна уже есть | `windows_lock.rs`, команды Tauri |
| Импорт | KeePass и Bitwarden, разбор форматов, новая именованная группа импорта, предварительная проверка и лимиты | Нет обработчиков импорта в ядре/командах |
| Экспорт | Собственный зашифрованный формат, история собственных записей, проверка файла и перенос аккаунта/сервера через экспорт–импорт | Нет обработчиков экспорта |
| Организация | Переименование/перемещение групп, менеджер тегов; универсальный редактор дополнительных полей для типов кроме документов | `groups.rs`, формы React |
| Полученные записи | Собственные группы/теги получателя оставлены на будущее по согласованному решению; сейчас отдельный раздел | Проект общих копий, интерфейс |
| TOTP | Вычисление одноразовых кодов и таймер; поле для хранения секрета есть | `model.ts`, редактор |
| Платформы | Выпуски Linux/macOS/Android/iOS с проверкой интеграции ОС; расширения браузеров и автозаполнение | Текущая упаковка и CI ориентированы на Windows |
| Серверная установка | Производственный интерактивный установщик, TLS/reverse proxy, сервис ОС, админ-настройки и процедуры эксплуатации. Текущий скрипт — запуск локального dev-сервера | `installer/`, `server/src/main.rs` |
| Миграции и совместимость | Полный процесс будущих миграций, административный перенос SQLite/PostgreSQL, матрица поддержки старых протоколов. База текущего прототипа 1 сознательно не переносится | Проверки schema/protocol и документация |
| Платная услуга | Биллинг, тарифы, реквизиты оператора, условия оплаты/возвратов и поведения при окончании оплаты | Требования раздела 33.6; реализации нет |
| Подготовка к выпуску | Независимый аудит, полный набор проверок криптоформатов/импорта/мобильных клиентов, документация эксплуатации и масштабирование | Имеющиеся автоматические проверки покрывают прототип |

Генератор паролей, локализация, дерево групп, архив, настройки, сочетания клавиш, контекстные меню и «О программе» уже реализованы; их нельзя продолжать перечислять как полностью отсутствующие. Автообновление и встроенные бэкапы не являются невыполненными требованиями: обновления выполняет пользователь, резервирование — администратор внешними средствами. Веб-версия и вложения отложены/исключены из текущего объёма.
