# Neruvalo: реализовано и остаётся сделать

Проверка исходников ветки `prototype/desktop-core`, версия 0.4.0, 30.10.2026. Это статус реализации, а не изменение требований. Исторические разделы руководства/спецификации могут описывать более ранние сборки.

## В этой итерации

- Импорты собраны во вкладке «Импорт» над настройками. Результат проверки KeePass показан кратко на странице; подробности доступны как локальный HTML-отчёт с таблицей исходных групп/UUID, записей, конкретных полей/вложений, исключений и причин. Последний завершённый отчёт сохраняется зашифрованным в профиле. Секретные значения в HTML не включаются.

- Дополнение 06.11.2026: вложения в обычных записях (формат содержимого 2), добавление/удаление при редактировании, сохранение через системный диалог, история, офлайн-чтение, локальные резервные копии и общие копии. Лимиты: 1 МиБ на файл, 4 МиБ и 16 файлов на запись. Старые клиенты требуют обновления для таких записей. Подробности и ограничения — раздел 15.4 спецификации.
- Импорт KeePass KDBX 3.1/4.0/4.1 через интерфейс: пароль, ключевой файл или оба; предварительный отчёт и явное подтверждение; новые ID и отдельная именованная группа; сохранение структуры, дополнительных полей, тегов, корзины и текущих вложений. Превышение лимитов вложений блокирует весь импорт. История и настройки KeePass не импортируются и отражаются в отчёте. Пакет публикуется атомарно; зашифрованный локальный журнал позволяет продолжить ту же операцию после перезапуска без дубликатов. Парсер keepass 0.17.0 (MIT) закреплён в `third-party/keepass` с ограничениями KDF, распаковки и глубины XML.

- Локальная настройка прокси до/после входа: автоматический/прямой/ручной HTTP(S)/SOCKS5(h), все серверные запросы идут через выбранный транспорт; в Windows конфигурация защищена DPAPI. Учётные данные прокси на других ОС пока не сохраняются.

- Общие копии по логину между аккаунтами одного сервера: отдельные зашифрованные контейнеры и sealed box ключа для каждого получателя, подпись контекста и контейнера владельцем.
- Атомарное обновление всех действующих копий вместе с новой версией оригинала. Изменение состава получателей конфликтует со старым сохранением.
- Отзыв владельцем, отказ получателя, прекращение доступов при архивировании оригинала/поддерева. Восстановление не возвращает прежние доступы. Повторная выдача создаёт новые ID.
- Получателю доступно только текущее содержимое, без API редактирования и истории чужого оригинала. Копия не содержит групп, тегов и служебных полей владельца.
- «Поделиться» в карточке/меню, проверка логина и ключей, подтверждение передачи, список получателей и отзыв. «Полученные», «Убрать у меня», индикатор и фильтр «С общим доступом».
- Базовое уведомление в приложении при обнаружении новых входящих копий во время загрузки/синхронизации. После нового входа уведомление может появиться повторно; это не полноценный центр непрочитанных уведомлений.
- Офлайн-чтение последней проверенной входящей копии; после успешного полного снимка прекращённые копии убираются из рабочего кеша и открытой карточки. Локальные служебные метки сохраняют максимальную ревизию, отпечаток текущего контейнера и факт прекращения доступа: повтор старого ID после подтверждённого удаления, снижение ревизии и иной контейнер с той же ревизией отклоняются. При полной потере кеша эти локальные знания теряются.
- Команды доступа к хранилищу в оболочке проверяют ожидаемый профиль аккаунта; отложенный запрос не выполняется для другого активного профиля.
- Протокол 2, новая схема сервера/кеша 2, явный отказ базе 1 без автоматического удаления. Содержимое обычных записей — формат 1, с вложениями — формат 2; групп — 2, общих контейнеров — 2.

Синхронизация пока полным снимком; действующие копии хранятся отдельно от истории оригиналов. Служебные строки прекращённых доступов остаются на сервере, их текущие контейнеры очищаются. В SQLite/PostgreSQL для согласованности снимков, доступа и записи используется единый транзакционный guard в metadata. Он намеренно сериализует записи всех аккаунтов прототипа; масштабирование и более узкие блокировки — отдельная работа.
