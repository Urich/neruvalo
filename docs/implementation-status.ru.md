# Neruvalo: реализовано и остаётся сделать

Проверка исходников ветки `prototype/desktop-core`, версия 0.4.0, 30.10.2026. Это статус реализации, а не изменение требований. Исторические разделы руководства/спецификации могут описывать более ранние сборки.

## В этой итерации

- Даты в редакторе: календарь в стиле выбранной темы приложения и региональное отображение, хранение выбранной даты в ISO. Для срока карты выбираются месяц и год. Пустой срок означает отсутствие ограничения; отдельной галочки «Бессрочный» нет. Импортированные временные метки сохраняются без изменения до редактирования даты.
- TOTP: локальная генерация через totp-rs (SHA-1/256/512, 6–8 цифр, настраиваемый период), предпросмотр и настройки в черновике, обратный отсчёт в карточке, копирование заново вычисленного кода с автоочисткой буфера. Секрет/URI маскируется. QR экспортируется на экран по явному действию, импортируется из PNG/JPEG/WebP локально. Поддержаны локальные, серверные, офлайн- и полученные записи. При смене записи/блокировке таймеры прекращаются, просроченный код не показывается во время обновления.

- Ускорение локального хранилища: индекс SQLite по записи/ревизии, выбор последних версий через группировку, общий кэш проверенных метаданных с проверкой отпечатка полного тела версии. Сохранение обновляет только одну запись интерфейса. Криптобиблиотеки в сборке разработки компилируются с оптимизацией; параметры KDF не меняются.
- Список записей: первоначальная загрузка при уже открытом хранилище, индекс без значений секретных полей и подгрузка значков и метаданных из БД порциями до 50 строк при прокрутке. Полное содержимое полей и описания вложений со ссылками сеанса передаются интерфейсу только при открытии карточки; байты и ключи файлов интерфейс не получает. Поиск и счётчики используют весь индекс. Индикатор загрузки и повтор при ошибке. У просроченных паролей отображается небольшой значок.

- Импорты собраны во вкладке «Импорт» над настройками. Результат проверки KeePass показан кратко на странице; подробности доступны в sandbox HTML-панели в памяти с таблицей исходных групп/UUID, записей, конкретных полей/вложений, исключений и причин. Отчёт и сводка доступны только в текущем сеансе, без сохранения в БД, файлы и backup; после блокировки/перезапуска остаётся лишь состояние незавершённой операции. Секретные значения в HTML не включаются.

- Файловая форма локального хранилища: редактируемое имя/путь, выбор нового или существующего файла, отображение полного пути. Существование файла переключает создание с подтверждением пароля на открытие с одним паролем; устаревшие результаты проверок пути игнорируются. Новые хранилища — один файл `.nvdb` с защищённым ключевым профилем внутри SQLite, прежние пары БД/`profile.json` читаются. Создание эксклюзивное, открытие без автоматического создания; хранилище используется по выбранному пути и запоминается без дубликатов.
- Совместимость хранилища проверяется до завершения открытия локальной базы, серверного офлайн-кеша и онлайн-входа; заголовки истории также проверяются. Неподдерживаемая схема/полезная нагрузка блокирует сеанс и возвращает вкладку «Открыть хранилище» с локализованной ошибкой. При синхронизации несовместимый снимок не записывается в кеш. Файлы во время проверки остаются зашифрованными.
- Дополнение 15.11.2026: отдельные зашифрованные блоки вложений; расшифровка файла только при сохранении на диск после выбора пути. Изменение записи, история, архив, локальный перенос и общий доступ обходятся без расшифровки файлов. Полезная нагрузка версии/общей копии 3 несовместима со старой; тестовые базы пересоздаются. Формат и независимый тестовый вектор описаны в `local-vault.md`.
- Дополнение 06.11.2026: вложения в обычных записях (формат содержимого 2), добавление/удаление при редактировании, сохранение через системный диалог, история, офлайн-чтение, локальные резервные копии и общие копии. Лимиты: 1 МиБ на файл, 4 МиБ и 16 файлов на запись. Старые клиенты требуют обновления для таких записей. Подробности и ограничения — раздел 15.4 спецификации.
- Импорт KeePass KDBX 3.1/4.0/4.1 через интерфейс в локальное хранилище без сервера или в серверную учётную запись онлайн: пароль, ключевой файл или оба; предварительный отчёт и явное подтверждение; новые ID и отдельная именованная группа; сохранение структуры, дополнительных полей, тегов, корзины и текущих вложений, иконок, исходных дат создания/изменения и срока действия записей; подстановка ссылок текущими значениями и нормализация TOTP KeePass/KeePassXC/KeeTrayTOTP. Превышение лимитов вложений блокирует весь импорт. История и настройки KeePass не импортируются и отражаются в отчёте. Пакет публикуется атомарно; зашифрованный локальный журнал позволяет продолжить ту же операцию после перезапуска без дубликатов. Парсер keepass 0.17.0 (MIT) закреплён в `third-party/keepass` с ограничениями KDF, распаковки и глубины XML.

- Локальная настройка прокси до/после входа: автоматический/прямой/ручной HTTP(S)/SOCKS5(h), все серверные запросы идут через выбранный транспорт; в Windows конфигурация защищена DPAPI. Учётные данные прокси на других ОС пока не сохраняются.

- Общие копии по логину между аккаунтами одного сервера: отдельные зашифрованные контейнеры и sealed box ключа для каждого получателя, подпись контекста и контейнера владельцем.
- Атомарное обновление всех действующих копий вместе с новой версией оригинала. Изменение состава получателей конфликтует со старым сохранением.
- Отзыв владельцем, отказ получателя, прекращение доступов при архивировании оригинала/поддерева. Восстановление не возвращает прежние доступы. Повторная выдача создаёт новые ID.
- Получателю доступно только текущее содержимое, без API редактирования и истории чужого оригинала. Копия не содержит групп, тегов и служебных полей владельца.
- «Поделиться» в карточке/меню, проверка логина и ключей, подтверждение передачи, список получателей и отзыв. «Полученные», «Убрать у меня», индикатор и фильтр «С общим доступом».
- Базовое уведомление в приложении при обнаружении новых входящих копий во время загрузки/синхронизации. После нового входа уведомление может появиться повторно; это не полноценный центр непрочитанных уведомлений.
- Офлайн-чтение последней проверенной входящей копии; после успешного полного снимка прекращённые копии убираются из рабочего кеша и открытой карточки. Локальные служебные метки сохраняют максимальную ревизию, отпечаток текущего контейнера и факт прекращения доступа: повтор старого ID после подтверждённого удаления, снижение ревизии и иной контейнер с той же ревизией отклоняются. При полной потере кеша эти локальные знания теряются.
- Команды доступа к хранилищу в оболочке проверяют ожидаемый профиль аккаунта; отложенный запрос не выполняется для другого активного профиля.
- Протокол и схема сервера/кеша 3, подпись версии записи 2, обязательные KDF/манифест и внешний ориентир отката. Прежние dev-форматы явно отклоняются без автоматического удаления. См. [формат и ограничения](database-integrity.md). Внешний payload — формат 3 с отдельными зашифрованными блоками; метаданные обычных записей — формат 1; групп — 2, общих контейнеров — 2.

Синхронизация пока полным снимком; действующие копии хранятся отдельно от истории оригиналов. Служебные строки прекращённых доступов остаются на сервере, их текущие контейнеры очищаются. В SQLite/PostgreSQL для согласованности снимков, доступа и записи используется единый транзакционный guard в metadata. Он намеренно сериализует записи всех аккаунтов прототипа; масштабирование и более узкие блокировки — отдельная работа.
