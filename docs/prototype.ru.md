# Neruvalo: запуск прототипа

Ветка: `prototype/desktop-core`. Изменения не объединяются с `main` без просьбы владельца.

## Что действительно реализовано

- Нативные Rust-ядро и консольный клиент, React-интерфейс внутри Tauri.
- OPAQUE 4.0.1: Ristretto255, TripleDH/SHA-512 и Argon2id, 64 MiB, 3 прохода, параллелизм 1.
- Создание аккаунта с проверкой кода email. В этой сборке письмо записывается в локальный закрытый dev-outbox; настоящей отправки SMTP и CAPTCHA пока нет.
- Случайный корневой ключ, XChaCha20-Poly1305, отдельные ключи версий, Ed25519-подписи.
- Создание и изменение записей, история, архивирование, возврат из архива, восстановление исторического содержимого новой версией.
- Подтверждение перед заменой открытого черновика кнопкой «Добавить запись», с сохранением ввода при отмене.
- Все восемь типов форм. Для прототипа TOTP хранит секрет, но не генерирует одноразовые коды.
- Проверка ревизий на сервере и блокировка повторного сохранения после конфликта до синхронизации.
- SQLite-кэш, офлайн-чтение истории, запрет записи офлайн.
- Сохранённые профили разных аккаунтов/серверов. В этой сборке одновременно разблокирован один активный аккаунт; переключение требует входа/разблокировки.
- Мастер-сертификат при регистрации, выбор восстановления без сертификата, восстановление с новым паролем и отзыв серверных сессий.
- Настраиваемый таймер 60/300/900 секунд или «никогда», значение хранится на сервере.
- Копирование поля, очистка буфера с проверкой, что он не изменился; 30/60/120 секунд или отключение.
- Обработчики блокировки сессии Windows и перехода в сон. Реальное поведение событий ОС проверяется отдельно на Windows.
- Серверные реализации SQLite и PostgreSQL через SQLx, схема БД версии 2, отказ от неизвестной схемы.
- Интерактивный установщик **локального dev-сервера** из исходников.

## Изменения интерфейса версии 0.2.0

- Навигация хранилища, типов, папок и архива видна только после входа / офлайн-разблокировки; блокировка скрывает её снова. На форме входа — «Пароль» и «Сервер».
- «Настройки» открываются отдельным экраном. До входа доступен язык; после входа также параметры безопасности и аккаунта. Открытие настроек не сбрасывает черновик и не отключает таймер блокировки.
- SVG-иконки одинаковы в навигации, списке, выборе типа и карточке; подписи сохраняются.
- Основной список — дерево групп, подгрупп и записей. Пустую группу можно создать отдельно через «Создать группу»; в карточке группы или контекстном меню — подгруппу либо запись любого из восьми типов. Группы общие для всех фильтров типов.
- Новая запись создаётся в выбранной группе; её тип можно сменить до сохранения. Если тип отличается от текущего фильтра, после сохранения включается «Все типы» и запись становится видна. Родителей новой записи приложение раскрывает.
- В форме записи выбирается «Группа» или «Корень списка». Строковый редактор путей папок и дерево папок слева удалены. Старые папки показываются как ветви основного дерева без изменения исходных записей.
- Имена и вложенность пустых групп сохраняются и синхронизируются как зашифрованные объекты. В офлайн-режиме дерево доступно только для чтения; раскрытие/сворачивание разрешено.
- Поиск оставляет родителей найденных записей; совпадение с именем группы показывает её содержимое с учётом фильтра типа. Во время поиска соответствующие ветви раскрываются. Пустые группы видны при фильтрации по типу.
- Убраны «Ваше хранилище», «Тихое место для важных вещей.», «/ ЛИЧНОЕ» и заголовки «ХРАНИЛИЩЕ» / «ТИПЫ ЗАПИСЕЙ» слева. Над списком — текущий логин и сервер разблокированного профиля, в том числе офлайн. Статус, пришедший после блокировки от старого запроса, не возвращает прежний аккаунт на экран.
- «Документы»: шаблоны паспорта, удостоверения личности, водительского удостоверения, визы, вида на жительство, страхового полиса и другого документа. Необязательные страна/организация и реквизиты без национальных масок, признак бессрочности, дополнительные именованные поля. Ведущие нули и старые/неизвестные поля сохраняются. Дополнительные поля маскируются как секреты.
- Правый клик / клавиша меню / Shift+F10 открывают меню Neruvalo для конкретной строки либо поля. Копирование не меняет выбор и не стирает черновик. Замена формы требует подтверждения; Escape или отмена сохраняют ввод. Меню поддерживает стрелки, Home/End, Enter и Escape.
- В текстовом поле доступны отмена/повтор, вырезание, копирование, вставка и выделение всего. Вставка получает буфер локально через Rust; содержимое никуда не отправляется.
- Команды «Скопировать логин» (`Ctrl+Shift+U`) и «Скопировать пароль» (`Ctrl+Shift+P`) действуют только в активном окне, для выбранной сохранённой записи вне текстовых полей и черновиков. Они доступны офлайн; блокировка запрещает копирование. Все способы копирования поля используют один Rust-обработчик и таймер очистки.
- «Настройки → Сочетания клавиш»: назначить, убрать, сбросить. При назначении нажмите комбинацию, Esc отменяет. Дубликаты и известные системные/редакторские сочетания отклоняются. Настройки и подсказки клавиш скрыты на мобильных устройствах; сами мобильные приложения ещё не выпускаются.

### Выбор сервера

Без аргументов поле «Сервер» показывает локальную историю успешных онлайн-входов и пункт «Другой сервер…». При первом запуске введите адрес вручную, например `http://127.0.0.1:8787` для локального dev-сервера. Последний успешный сервер выбирается первым. Адреса не проверяются сетевыми запросами при показе списка. История хранит только адреса и доступна текущему пользователю ОС; старые успешные профили также предлагаются после обновления.

Чтобы закрепить сервер на время запуска:

```powershell
.\neruvalo-desktop.exe --server https://vault.example.org
# Для локального dev-сервера:
.\neruvalo-desktop.exe --server http://127.0.0.1:8787
```

Допускается также `--server=URL`. Меню выбора скрывается; адрес показан только для чтения. Ограничение проверяется в Rust для входа, регистрации, офлайн-профиля и восстановления сертификатом. Чужой сертификат не переключит сервер; некорректный аргумент не вызывает перехода к серверу из истории. В следующем запуске без аргумента возвращается обычный выбор. Внешние серверы требуют HTTPS; возможность производственного размещения самого сервера по-прежнему не готова.

## Что пока не реализовано

Интерфейс переведён на en, ru, es, fr, de, pt, zh-Hans, zh-Hant, ja, hi, ar. Локаль Windows определяется нативно; на Linux учитываются LC_ALL / LC_MESSAGES / LANG. Неподдерживаемая локаль и отсутствующее сообщение используют английский. Каталоги входят в пакет; внешние сервисы перевода не используются. Ручной выбор в «Настройки → Интерфейс» действует сразу и сохраняется на этом устройстве. Для арабского применяется RTL, значения секретов изолированы от направления интерфейса.

QR (общие копии по логину реализованы в 0.4.0), редактор дополнительных полей для остальных типов (для документов уже доступен), переименование, перемещение и удаление самих групп, менеджер тегов, импорт/экспорт, генерация TOTP, Windows Hello, замена/отключение сертификата после регистрации, обычная смена пароля, удаление аккаунта, смена email, список/отзыв отдельных устройств, WebSocket/delta sync, SMTP/CAPTCHA, полноценная серверная миграция и производственная установка.

Сейчас синхронизация загружает полный снимок истории; ограничения большого хранилища ещё не решены. Неизвестные типы защищены проверками ядра; гарантия совместимости будущих версий требует дальнейших тестов.

Прототип не проверен независимым аудитом. Использовать только вымышленные данные. Нет автоматически обновляемого ПО и встроенных бэкапов. Период очистки буфера и сочетания клавиш сохраняются локально для этого устройства; тайм-аут аккаунта хранится на сервере.

## Требования

- Rust stable и C/C++ toolchain. Для Windows: Visual Studio Build Tools с Desktop development with C++, Windows SDK и Microsoft Edge WebView2 Runtime.
- Node.js 22.22.2+ или 24.15.0+ и npm для интерфейса.
- Для Linux-сборки оболочки Tauri дополнительно нужны системные зависимости GTK/WebKit; первая целевая ОС — Windows.
- PostgreSQL нужен только при выборе этого backend; отдельная пустая БД обязательна.

Команды выполняются из корня клонированного репозитория, если не указано иначе.

```bash
git clone --branch prototype/desktop-core https://github.com/Urich/neruvalo.git
cd neruvalo
```

## Сервер на Windows

PowerShell:

```powershell
New-Item -ItemType Directory -Force local-data | Out-Null
$env:NERUVALO_DEV_MODE = 'true'
$env:DATABASE_URL = 'sqlite://local-data/server.sqlite3?mode=rwc'
$env:NERUVALO_DEV_OUTBOX = 'local-data/dev-outbox'
cargo run --locked -p neruvalo-server
```

Сервер слушает только `127.0.0.1:8787`. Код намеренно отказывается от внешнего listener, поскольку SMTP, CAPTCHA и производственная политика доступа ещё не реализованы. Не отключать эту защиту ради публикации прототипа в интернете.

Для абсолютного пути Windows используйте форму `sqlite:C:/Neruvalo/server.sqlite3?mode=rwc` без `//` перед буквой диска. Для пути со специальными символами безопаснее сформировать строку так:

```powershell
$databaseFile = Join-Path $PWD 'local-data/server.sqlite3'
$env:DATABASE_URL = 'sqlite:' + [Uri]::EscapeDataString($databaseFile) + '?mode=rwc'
```

## Сервер на Linux

```bash
mkdir -p local-data
umask 077
export NERUVALO_DEV_MODE=true
export DATABASE_URL='sqlite://local-data/server.sqlite3?mode=rwc'
export NERUVALO_DEV_OUTBOX='local-data/dev-outbox'
cargo run --locked -p neruvalo-server
```

Для PostgreSQL вместо SQLite укажите URL отдельной БД:

```bash
export DATABASE_URL='postgres://neruvalo:YOUR_PASSWORD@127.0.0.1:5432/neruvalo'
```

Не публикуйте URL с паролем в issue, логи и репозиторий. OPAQUE setup и `server_id` сохраняются в таблице `metadata`: не удаляйте её при перезапуске.

Проверка:

```bash
curl http://127.0.0.1:8787/health
```

### Интерактивная установка

```bash
./installer/install-dev.sh
```

Скрипт спрашивает каталог, SQLite/PostgreSQL и порт; показывает итог; собирает release-сервер и создаёт `run.sh`. Существующую установку не перезаписывает, зависимости ОС не устанавливает, службы и автозапуск не включает. Пароль PostgreSQL вводится скрыто. Готовность проверяется после ручного запуска командой `/health`.

Для клиента Windows и сервера Linux можно использовать SSH-туннель:

```powershell
ssh -N -L 8787:127.0.0.1:8787 user@server
```

На клиенте укажите `http://127.0.0.1:8787`. HTTP разрешён только для loopback; для удалённых адресов клиент требует HTTPS.

## Приложение Windows

### Готовая тестовая сборка

На вкладке **Actions → Prototype checks** открыть последний успешный запуск для этой ветки и скачать артефакт `neruvalo-windows-prototype`. Распаковать ZIP в отдельный каталог, затем:

1. Запустить `start-dev-server.cmd` и оставить окно открытым. База SQLite и файлы тестовых писем появятся в `local-data` рядом с программой.
2. Запустить `neruvalo-desktop.exe`, создать аккаунт на `http://127.0.0.1:8787`.
3. Взять код подтверждения из `local-data/dev-outbox/<ticket>.txt`.

В комплекте также есть консольный `neruvalo-cli.exe`. Для готовых файлов Rust и Node.js не нужны; для интерфейса требуется Microsoft Edge WebView2 Runtime. Пакет не подписан и предназначен для проверки на вымышленных данных. Это переносимая тестовая сборка, не установщик службы Windows.

### Запуск из исходников

Во втором терминале:

```powershell
cd apps/desktop
npm ci
npm run tauri -- dev --features desktop
```

Путь к данным по умолчанию определяет Tauri через `app_local_data_dir`. Для проверки двух независимых устройств задайте разные каталоги:

```powershell
$env:NERUVALO_CLIENT_DIR = "$env:LOCALAPPDATA\NeruvaloPrototype-device-a"
npm run tauri -- dev --features desktop
```

Использование:

1. «Создать аккаунт», сервер `http://127.0.0.1:8787`, логин в нижнем регистре (латиница, цифры, `_`, `-`), email, мастер-пароль минимум 12 символов.
2. Выбрать восстановление сертификатом либо отказаться от него.
3. Найти указанный файл `<ticket>.txt` в dev-outbox сервера. Он имитирует письмо подтверждения. Скопировать значение после `Confirmation code:`.
4. Подтвердить регистрацию и сохранить мастер-сертификат, если выбран. Файл не защищён паролем. Существующий файл не перезаписывается.
5. Войти и создать запись. Сервер не получает её название, поля или пароль в открытом виде.
6. Открыть «История» и развернуть нужную версию: доступны её поля, заметки, папка и теги. Секретные поля раскрываются отдельно. «Восстановить новой версией» сохраняет выбранное содержимое текущей ревизией, не переписывая прошлое.
7. Для офлайн-чтения заблокировать хранилище, выбрать сохранённый профиль и ввести мастер-пароль.
8. Для восстановления ввести новый пароль в поле входа, нажать «Восстановить доступ» и выбрать сертификат; затем войти заново.

Сборка:

```powershell
npm run tauri -- build --features desktop
```

Сборка требует установленных системных инструментов. Рабочие исполняемые файлы/установщики, если они успешно собраны, находятся в `target/release` и `target/release/bundle` в корне workspace. Наличие исходников не означает, что на текущем коммите опубликован готовый установщик.

В workflow `Prototype checks` Windows-задача собирает debug `.exe` приложения, сервера и CLI и проверяет запуск сервера на SQLite. Артефакт появляется только после успешных проверок; это не подписанный production-релиз.

## Консольный клиент

Позволяет проверить ядро без Tauri:

```bash
cargo run --locked -p neruvalo-client --bin neruvalo-cli -- register alice alice@example.test --certificate /absolute/path/alice-recovery.json
cargo run --locked -p neruvalo-client --bin neruvalo-cli -- login alice
```

Пароли вводятся скрыто, не передаются аргументами командной строки. Для отказа от восстановления не указывайте `--certificate`.

Команды открытого хранилища: `list`, `new`, `show ID`, `history ID`, `archive ID`, `restore ID`, `sync`, `timeout SECONDS`, `quit`. `show` намеренно выводит выбранную запись в открытом виде; не использовать на записываемом или общем терминале.

```bash
cargo run --locked -p neruvalo-client --bin neruvalo-cli -- profiles
cargo run --locked -p neruvalo-client --bin neruvalo-cli -- offline PROFILE_ID
cargo run --locked -p neruvalo-client --bin neruvalo-cli -- recover /absolute/path/alice-recovery.json
```

## Проверки

```bash
cargo fmt --all --check
cargo clippy --locked --workspace --exclude neruvalo-desktop --all-targets -- -D warnings
cargo test --locked --workspace --exclude neruvalo-desktop
cd apps/desktop
npm ci
npm test
npm run build
```

SQLite integration тесты поднимают настоящий HTTP-сервер на случайном loopback-порту и используют настоящие OPAQUE/Argon2id и SQLite.

Для PostgreSQL создать **одноразовую пустую тестовую БД**, затем:

```bash
NERUVALO_TEST_DATABASE_URL='postgres://user:password@localhost:5432/neruvalo_test' \
  cargo test --locked -p neruvalo-client --test end_to_end -- --test-threads=1
```

**Внимание: PostgreSQL-тест очищает схему `public` в переданной тестовой БД. Никогда не указывать рабочую БД.** Это только тестовый код. CI использует отдельный контейнер.

## Форматы и ограничения

- Номер протокола 1, серверная и локальная схемы 1, пакет 0.1.0.
- Совместимость с будущими форматами не обещается прототипом; миграции пока ограничены проверкой версии.
- Криптографические контексты включают стабильные IDs сервера/аккаунта/версии.
- Подписываемые поля имеют фиксированный порядок с 64-битными big-endian длинами. Payload JSON рекурсивно сортирует ключи; полезная нагрузка конвертов не содержит произвольных float.
- API возвращает только шифротекст для записей; профили содержат публичные ключи и зашифрованные оболочки.
- Сессия сервера живёт 12 часов; её токен хранится в памяти клиента, а хеш — на сервере. Это отдельное ограничение от локального тайм-аута.
- Нормальная блокировка пока очищает локальный контекст; повторное открытие выполняется мастер-паролем. Hello будет добавлен отдельно.
- Секреты временно попадают в память WebView при отображении; гарантированное физическое стирание всех копий строк не заявляется.
- Старый пароль может открывать старую офлайн-копию после восстановления на другом устройстве. Это ограничение согласованного бессрочного офлайн-доступа.
- Подпись и AEAD не защищают от полностью скомпрометированной ОС, подмены первого доверенного клиента или злонамеренного получателя.


## Обратная связь после проверки сборки 36b8792

Сборка в целом проверена владельцем. Текущее представление папок отклонено; его предстоит убрать из интерфейса и отдельно спроектировать замену, сохранив существующие данные и историю. На главном экране предстоит убрать «Ваше хранилище», «Тихое место для важных вещей.» и заменить «логин / ЛИЧНОЕ» актуальными логином и сервером. Размещение компактным блоком на прежнем месте предложено для обсуждения.

Это требования следующей итерации, а не изменения уже выданного пакета. Продолжается только документация; реализация и сборки приостановлены. Подробности — раздел 30 спецификации.


### Следующее представление списка: дерево групп

Согласовано направление замены текущих папок: дерево групп и подгрупп непосредственно в основном списке записей. Группу можно создавать отдельно и пустой из любого раздела типов; внутри — подгруппы и записи разных поддерживаемых типов. Подробности и отдельно отмеченные предложения по фильтрам/действиям — раздел 31 спецификации. Это документация следующей итерации; в выданной сборке новое дерево ещё не реализовано.


## Версии и совместимость групп

Версия приложения — **0.2.0**. Протокол и схема серверной/локальной БД остаются версии 1: сервер хранит непрозрачные зашифрованные версии. Обычные записи сохраняют формат 1; метаданные группы используют отдельный внутренний формат 2. Новая версия читает старые записи и кэш без их массового переписывания. Формат описан в `docs/groups-format.md`.

Для работы с группами на всех устройствах используйте клиенты 0.2.0 или новее. Клиенты 0.1.x не понимают новый объект группы; прямую совместную работу старых клиентов с хранилищем, содержащим группы формата 2, эта версия не гарантирует. Совместимость чтения старых данных новым клиентом проверена отдельно.

Старый путь папки остаётся в оригинале и истории. До первого изменения дерево показывает его виртуальными узлами. При создании подгруппы/записи внутри старого пути либо сохранении записи в таком узле необходимые группы сохраняются отдельно; исходные версии не изменяются. Идентификаторы таких групп выводятся из секретного корневого ключа аккаунта и пути: повторная обработка на другом устройстве не создаёт дубликатов и не открывает путь серверу. Выбор «Корень списка» задаётся явно и не возвращает запись в прежнюю папку. Операции с такими группами требуют онлайн-доступа. Поддерживается до 64 уровней сохраняемых групп.


## Следующая итерация после приёмки 0.2.0 — только документация

Требования раздела 33 спецификации пока **не реализованы** в выданном пакете:

- Архивирование целых групп с подгруппами через контекстное меню. Подтверждено восстановление всей группы либо отдельных элементов: восстановление всей ветви включает ранее архивированные записи, выборочное оставляет соседей в архиве. Для сохранения места элемента описано рабочее правило восстановления минимальной цепочки предков. Атомарность и пакетный протокол ещё требуют технического проектирования.
- При активном фильтре типа скрываются группы без подходящих записей во всём поддереве; без фильтра пустые группы доступны. Это заменяет поведение 0.2.0, где пустые группы видны при любом типе.
- Выпадающий выбор типа с иконками вместо кнопок; удаление строки `PROTOTYPE · 0.2` из левой панели.
- «О программе» последней кнопкой под «Настройки»: фактическая версия/сборка, авторы, AGPL-3.0-only, соответствующие исходники, лицензии/уведомления зависимостей и сведения о проекте, в том числе офлайн.
- Управляемый сервер владельца проекта предполагает платный доступ; условия услуги проектируются отдельно от свободной лицензии исходников. Конкретные цены, оператор и платёжные правила пока не определены.

Код, сборки, упаковка и CI снова приостановлены по просьбе владельца. Исторические описания реализованной версии выше остаются справкой о 0.2.0, а не подтверждением готовности новых функций.

## Версия 0.3.0 — архив групп и сведения о программе

Раздел «Следующая итерация» выше описывал паузу проектирования; 30.10.2026 владелец возобновил реализацию. Теперь:

- В контекстном меню и карточке группы доступны архивирование и восстановление всей ветви. Подтверждение учитывает все типы и скрытые фильтром записи.
- Отдельную запись можно восстановить внутри архивной ветви: необходимые родители возвращаются, соседи остаются в архиве. Пустые группы тоже архивируются. История не удаляется.
- При выбранном типе пустые для этого типа ветви скрыты. Без фильтра видны самостоятельные пустые группы. После создания группы фильтр сбрасывается.
- Тип новой записи выбирается списком с иконками. Внизу панели добавлено «О программе», прежняя надпись PROTOTYPE над фильтрами убрана.
- «О программе» содержит версию, commit, ОС/архитектуру, исходники, AGPL, сторонние компоненты и ссылки на сообщения о проблемах. Тексты лицензий доступны офлайн. Управляемый сервер описан как отдельная будущая платная услуга.

Для этих функций используйте клиент и сервер 0.3.0 вместе. Данные 0.2.0 читаются, схема SQL не меняется. Старые клиенты не обеспечивают правила групп. При конфликте синхронизируйте устройства и повторно откройте запись/группу. Для замены архивной записи исторической версией сначала восстановите саму запись.

Сборка `npm run build` формирует сведения о лицензиях из закреплённых npm/Cargo-зависимостей; нужны Node.js и Cargo. В переносимом Windows-пакете поставляются клиент, сервер, CLI, запуск dev-сервера, эта инструкция, лицензия, уведомления зависимостей и `source.zip` соответствующего commit. Это всё ещё локальный прототип, а не готовый публичный платный сервис.

### Генератор паролей

Кнопка «Сгенерировать пароль» рядом с полем пароля заполняет черновик локально. Чтобы сохранить результат, нажмите обычную кнопку «Зашифровать и сохранить». Повторная генерация заменяет текущее значение поля. Длина и наборы символов задаются в «Настройки → Генератор паролей» и сохраняются на устройстве. По умолчанию: 20 символов, буквы обоих регистров, цифры, спецсимволы, без похожих знаков. Доступны длины 8–128; каждый включённый набор обязательно используется.

## Версия 0.4.0: общие копии и новая база

Используйте клиент и сервер 0.4.0 вместе: протокол и схема БД/кеша — 2. По согласованию с владельцем база 0.3.0 не переносится. Старая база явно отклоняется без удаления; для теста распакуйте пакет в новую папку и запустите `start-dev-server.cmd`, затем `start-desktop.cmd`. Второй скрипт задаёт отдельный кеш `local-data/client-v04`, сохраняя прежний кеш приложения. Для нового сервера зарегистрируйте тестовые аккаунты заново.

В меню/карточке собственной активной записи выберите «Поделиться», введите логин другого аккаунта этого сервера, проверьте идентичность/ключи и подтвердите передачу. Можно предоставить доступ нескольким получателям и отозвать отдельный доступ. Содержательные поля и заметки передаются целиком; группы и теги владельца исключены.

«С общим доступом» фильтрует собственные записи с действующими получателями, «Полученные» показывает входящие копии только для чтения. Получатель может копировать поля и выбрать «Убрать у меня», не затрагивая других. Для проверки изменений/отзыва на другом устройстве нажмите «Синхронизировать». Офлайн остаётся последнее синхронизированное содержимое; мгновенный отзыв на отключённом устройстве невозможен.

Сохранение оригинала обновляет все действующие копии атомарно. Архивирование оригинала или группы прекращает доступы; восстановление не создаёт их заново. При конфликте набора получателей синхронизируйте устройства и заново откройте запись перед сохранением. Повтор неизвестной операции использует тот же ID и сохранённый зашифрованный запрос.

Полный актуальный список оставшихся требований: [implementation-status.ru.md](implementation-status.ru.md). QR, delta/WebSocket, полноценные уведомления, управление аккаунтом, импорт/экспорт, Hello и производственный сервер ещё требуют разработки. Исторические списки выше относятся к прежним версиям.
